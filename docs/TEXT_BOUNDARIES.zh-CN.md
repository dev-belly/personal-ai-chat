# 文字与边界检查

2026-11-17 对 Personal AI Chat 和 GitHub 主页的 87 个现有文本文件进行 UTF-8 字节扫描，
没有发现非法字节、替代字符或 NUL。主页既有文档检查也没有发现高置信乱码特征。
源码、配置与文档现在分别通过各仓库的文字检查持续验证；扫描通过不等于任意设备字体都覆盖全部字形。

## 复现并修复的编码边界

| 触发 | 修复后的行为 |
| --- | --- |
| 自动标题第 80 个 UTF-16 单元落在 emoji 中间 | 用 `Intl.Segmenter` 按完整字素截断，消息原文完整保留 |
| 请求中的非法或截断 UTF-8 字节 | 严格流式解码，返回 400，不静默生成替代字符，不调用模型 |
| JSON 转义携带单独的高/低代理项 | 共享 Zod 契约拒绝；页面保留可修改的输入并显示提示 |
| 上游两段文本分别包含一个 emoji 的高、低代理项 | 缓冲尾部高代理项，等后续字符完整后再编码和显示 |
| 上游结束时仍留有半个字符 | 本轮失败；已显示完整文字保留为未完成内容，不进入成功上下文 |
| 本机记录或导出带有不完整字符、超长用户消息 | 读写校验拒绝，已有数据不被静默覆盖 |

同一 Unicode 缓冲策略覆盖服务器流、标准 UI 客户端和兼容 SSE 客户端。
标准 UI 流在交给 SDK 解码前验证 UTF-8 字节，防止替代解码掩盖传输损坏。
字节与字符上限仍独立执行；有效中文、组合字符和 emoji 可以跨请求字节块正常传递。

## 检查覆盖

- `npm run check:text`：源码、配置、文档的严格 UTF-8，以及替代字符、常见二次解码特征和异常控制字符；只报告，不猜测编码或改写文件。
- `npm test`：实际请求体逐字节读取、模型到两种客户端的消息流、坏字符失败、本机保存/加载/导出与文件扫描回归。
- `npm run check:http`：生产 Next.js / AI SDK / 本地模型替身的 41 项检查，含非法编码拦截、emoji 跨事件拼接及错误传播。
- `npm run check:browser`：在原有取消、错误、跨标签页、存储降级和 Markdown 行为之外，验证标题、Unicode 刷新恢复及输入错误修正。

单元和浏览器替身不证明所有供应商、字体和线上环境都通过验收。项目没有导入功能；
导出只验证当前公开格式。会话上限、并发事务、Markdown 链接/图片边界和请求预算继续由各自检查覆盖。
