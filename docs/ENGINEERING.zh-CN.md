# 页面、接口与验证

Personal AI Chat 将 Next.js / React 页面和模型代理路由放在同一仓库。
默认本地模拟用于试用界面；真实模式把消息交给服务端配置的模型。

## 从一次发送读代码

| 环节 | 实现 | 需要保持的行为 |
| --- | --- | --- |
| 输入与页面状态 | [app/page.js](../app/page.js) | 中文输入法确认不误发送；等待、取消、失败重试与新会话有明确状态。 |
| 历史上下文 | [lib/chat-client.mjs](../lib/chat-client.mjs) | 仅保留成功的完整轮次，删除最旧的整轮以满足消息数、字符数和序列化字节限制。 |
| 配置与鉴权 | [app/api/chat/route.js](../app/api/chat/route.js) | 浏览器使用独立访问口令；上游 API Key 只由服务端读取。 |
| 请求体与角色契约 | [lib/chat-validation.mjs](../lib/chat-validation.mjs) | 累计实际读取字节；限制消息长度和总字符数；角色从 user 开始交替并以 user 结束。 |
| 模型边界 | [app/api/chat/route.js](../app/api/chat/route.js) | 透传请求取消信号，设置超时，不自动重试；将内部错误转成可重试的公开错误。 |

页面用递增的请求标识隔离会话。清空或切换模式会使旧标识失效，较晚返回的响应不能覆盖新会话。
失败请求留在页面以供重试，但不进入下一次模型上下文。
聊天数据目前只保留在页面内，持久化与多用户会话管理尚未实现。

## HTTP 返回契约

| 场景 | HTTP 状态 | 对调用方的意义 |
| --- | ---: | --- |
| GET 配置状态 | 200 | 仅返回 `configured`，并使用 `Cache-Control: no-store`。 |
| 有效文本回复 | 200 | 返回 `content`；页面才会保存成功轮次。 |
| JSON、角色或长度不合法 | 400 | 修正输入后再发送。 |
| 独立访问口令不匹配 | 401 | 检查页面访问口令。 |
| 请求体超过 64 KiB | 413 | 缩短请求；上游不会被调用。 |
| 上游限流 | 429 | 等待后手动重试。 |
| 上游认证或其他服务错误 | 502 | 返回公开错误，不暴露上游内部详情。 |
| 空内容、纯空白或仅工具块 | 502 | 没有可显示的回复，保留失败与重试状态。 |
| 服务端配置未完成 | 503 | 先完成部署配置；不调用模型。 |

空文本曾被替换成“无响应内容”并返回 200，这会把占位文字当作正常助理回复。
现在仅有实际非空文本才返回成功。工具调用目前没有执行协议，因此纯工具响应也不会冒充文本答案。

## 分别验证工具函数与真实 HTTP

```bash
npm ci
npm test
npm run build
npm run check:http
npm run build:worker
```

`npm test` 检查上下文裁剪、UTF-8 字节预算、输入法和请求校验等可独立行为。
`check:http` 启动生产 Next.js 子进程与本地 HTTP 模型替身，检查以下 12 项：

1. 配置状态不泄露配置值且不缓存。
2. 错误口令被拦截，上游调用数保持为零。
3. 非法 JSON 被拦截。
4. 非法角色顺序被拦截。
5. 超大请求在模型调用前被拦截。
6. 中文消息实际经过 HTTP 和 SDK 到达本地上游，仅转发规范化字段。
7. 上游认证错误转换为 502，隐藏内部错误且不自动重试。
8. 上游限流保留 429，隐藏内部错误且不自动重试。
9. 空内容不能成为成功回复。
10. 空白文本不能成为成功回复。
11. 纯工具响应不能成为成功回复。
12. 未配置的应用返回 503 且不调用上游。

替身监听 `127.0.0.1` 的随机端口，应用使用脚本生成的测试配置。
脚本退出时停止子进程并关闭连接；不接触真实模型或现有部署。
[CI](../.github/workflows/ci.yml) 在生产构建后运行同一 HTTP 检查，再验证 Workers 构建。

构建链对 `glob` 的定向覆盖使用已修复的 14.0.6，锁定的依赖解析保留 `minimatch` 11.0.8。
[构建依赖测试](../test/build-dependencies.test.mjs)从 OpenNext 的实际依赖树加载压缩器，
验证字符串和数组形式的通配符输入都能找到文件、生成压缩代码，并保持执行结果。
审计与两种构建也进入同一 CI；修改覆盖版本时应一起检查。

这些检查验证 Node.js 生产服务到本地模型边界的请求行为。
浏览器交互、Cloudflare 线上运行和真实模型响应仍需在对应环境中另外验收。
