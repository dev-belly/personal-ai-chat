# 本机会话与流式 Markdown

点击“保存会话”后，当前内容才写入本浏览器。打开已保存记录后可以继续聊天，
再点击“更新保存”提交新版本；新消息不会自动落盘。支持标题搜索、逐条删除和当前会话 JSON 导出。

## 数据与并发

| 表 / 字段 | 用途 |
| --- | --- |
| `summaries` | UUID、标题、模式、修订号、创建/更新时间、消息数量；按更新时间读取目录 |
| `bodies` | 同一 UUID 对应消息体；打开记录时读取，不随目录全部载入 |
| `revision` | 保存和删除必须匹配读到的版本；拒绝旧标签页覆盖新内容 |
| 允许的消息字段 | role、content、完成状态，以及用于失败重试的文字和公开请求编号 |

两张表同一事务写入或删除，写入失败不会留下只有摘要的半条记录。
已删除 ID 不能通过旧更新复活。并发写同一修订只有一个成功，其余显示冲突并保留当前页面文字。
Dexie `useLiveQuery` 更新目录，当前聊天只有用户重新打开记录时才替换。

读写均使用 Zod 检查。每条记录最多 400 条消息、正文序列化后 512 KiB；最多 100 条记录，
达到限制时拒绝新写入，不自动淘汰已有记录。损坏记录读取失败不会清空当前聊天或自动删除原始记录。
浏览器存储不可用时显示原因，输入、回复与 JSON 导出仍可使用。

## 请求与存储的生命周期

打开历史先读取并验证记录，成功后才中止当前请求、推进请求代次并恢复消息。
恢复时移除内部请求标记，把未完成的用户发送/助理回复分别标为 failed / incomplete；
后续上下文仍只选成功的完整轮次。旧请求后到达的动作不能修改恢复记录。

存储操作有独立代次。例如点击保存后立即新建会话，已发出的事务仍可完成，
但它的回调不能把新会话重新选成刚保存的记录；再次保存会创建独立记录。

保存/导出显式投影消息字段，不包含页面访问口令、上游 API Key 或内部请求代次。
消息原文会保留，包括用户自行写入的内容。它们是当前站点在本浏览器中的数据，
没有账号、服务端同步或加密备份；清除站点数据会移除本机记录。
导出采用 `personal-ai-chat` / version 1 JSON，目前不提供导入。

## Markdown 展示边界

Streamdown 渲染增量文本、未闭合代码围栏和表格，代码插件使用 Shiki 高亮。
进行中的代码块不能复制；完成后复制原始代码。Streamdown 默认净化流程保留，
自定义链接只接受 HTTP、HTTPS、mailto，打开新窗口带 `noopener noreferrer`。
图片转成替代文字，不自动请求模型输出中的图片 URL。没有启用 Mermaid 或工具执行插件。

Tailwind CSS 4 只导入 theme 与 utilities，扫描 Streamdown / code 插件的样式类；
原有全局 reset 在 base layer，保留当前暗色界面和手机宽度行为。

## 如何验证

- `npm test`：实际 Dexie / fake-indexeddb 事务，包含回滚、版本并发、删除、大小限制、损坏数据及请求恢复隔离。
- `npm run check:browser`：生产 Next.js + Chromium 验证刷新、保存与新建并发、跨标签页、JSON 下载、继续上下文与存储降级。
- 同一浏览器检查验证增量 Markdown、表格、高亮、剪贴板内容、危险链接/脚本与追踪图片，并保存桌面/手机截图。
- `npm run build` / `npm run build:worker`：两种部署产物编译；真实模型与线上运行单独验收。
